# 自动招聘闭环设计（猎聘）

日期：2026-09-25
状态：业务规则已逐项与用户确认；能力验证（推荐绑定/附件下载）已真机通过

## 1. 目标

开启服务后，每天自动运行：获取平台推荐 → 读取在线简历 → 期望职能校验 → AI 评分 → 通过自动打招呼 → 对方回复后索要简历 → 附件自动收集入库；同时轮询主动来信。

## 2. 运行策略（已确认）

- **调度**：北京时间每天 09:00–18:00 每整点执行一轮（含 18:00，周末与节假日同样执行）， 服务停机期间不补跑。
  （2026-09-28 节拍改造：单轮在 50 分钟窗口内**平摊匀速**执行，详见《2026-09-28-round-pacing-design.md》；命中验证页先冻结退避复测一次，再命中才熔断。）
- **岗位范围**：全部「在招且已关联猎聘职位」的岗位；新增符合条件岗位自动纳入。
- **单轮顺序**：先处理来信与附件，再逐岗位拉推荐、评分、打招呼。
- **配额与批量**：取消系统自设的每账号每日打招呼配额；单轮打招呼上限每岗位 15（2026-09-28 熔断治理由 50 降档，配置 `hr-agent.auto-recruit.greet-batch-limit`，env 可调），评分符合即打招呼；轮内自动索要上限 5（`ask-batch-limit`）、轮内简历详情读取总预算 30（`resume-detail-round-limit`）；发送间隔 60 秒、账号串行、防重复与风控熔断（不自动解除）。
- **运行时开关（2026-09-26）**：界面「自动外发」总闸（存库持久化，仅 ADMIN 可见可操作）——OFF 时轮次照常运行（检测回复/已读、附件下载、评分、拉推荐），仅跳过打招呼与索要（攒着，开启后自动补做）；轮次开始时判定、跑完本轮才生效；手动操作（立即运行一轮/高级操作）不受开关限制；启动配置 `enabled` 降级为库中无值时的首次种子。
- **异常处理**：安全验证/登录失效/熔断 → 本轮立即停止并告警，人工接管。

## 3. 业务流程与门禁

### 3.1 推荐通道（主动）

1. 每岗位拉取推荐（显式 jobId，真机验证 20/20 精确绑定；无效 ID 拒绝零回退）。
2. 按 (resume_id, jd_id) 判断该岗位下是否已处理，仅处理该岗位新增；同一人在其他岗位的记录不阻止本岗位评估。
3. 读取在线简历详情 → **期望职能同类型校验**（不要求名称全等；反例直接拦截；证据缺失 → 待确认）。
4. 评分（按岗位门槛）→ 通过 → **发送前复核**（职能匹配 + 评分通过 + 门槛已确认 + ejobId 正确）→ 打招呼。
5. 对方回复 → 索要简历（resume_id，非 im_id）→ 同意后下载附件入库。

### 3.2 来信通道（被动）

1. 轮询会话列表（固定取 100 条，CLI 上限；新招呼会把旧会话挤出较小窗口导致漏检，2026-09-26 实测）。
2. 已知候选人：对方最后发言且无入库记录 → 经 `attach-fetch` 纯接口获取附件（检测/下载详见 4.2；**不受分数/门槛限制**，开关 OFF 也照常收集）→ 校验入库；仅文本回复 → 评分通过才索要；**对方已读我方最新消息（会话级 oppositeRead）同样触发索要（不等回复，2026-09-26 新增）**。
3. 陌生来话：从会话消息的简历卡片载荷提取简历标识；提取成功且有可关联岗位 → 走评分门禁；**提取失败或无法关联岗位 → 人工待分配**（不猜测身份，不自动评分/索要；已有附件可入库并标记待分配）。

### 3.3 门槛确认为外发前提

- 岗位发布时：AI 依据 JD 给出建议门槛与理由 → 用户确认或修改（记录确认人/时间）。
- 存量同步岗位：同样先确认，确认前只收集来信与附件，**禁止一切自动外发**。

### 3.4 附件入库标准（真机验证结论）

- 唯一可行路径：打开会话 → 附件卡片 → 预览 → **浏览器下载通道**（CDP 捕获）；直连附件 URL 返回 403，不可用。自动打开会话会将会话标记为已读（已知副作用，已确认接受）。
- 入库条件：下载完成 + 文件签名/结构校验 + SHA-256 记录 + 存储成功；任一失败 → 不入库、留待处理重试。
- 候选人库（已收简历视图）**只显示入库成功的人**。

## 4. 技术方案

### 4.1 CLI 扩展（fork，`tools/liepin-cli`）

- 新增 `attach-download`：输入会话方 im_id + 输出目录；打开会话（会标记已读，已知副作用已接受）→ 定位附件卡片 → 触发预览下载 → CDP 捕获文件 → 校验 PDF 签名与哈希 → 输出结构 JSON。
- 复用已修复的 `greet --ejobId/--message`、`recommend --jobId`、期望职能三态判定（resume.ts）。
- 现有命令不引入新的反检测逻辑。

### 4.2 后端

- **调度**：新增 `AutoRecruitScheduler`（cron：每天 09:00–18:00 每小时，含周末与节假日）；任务经现有 search_task 队列串行执行；防重叠（岗位任务未完成则本轮跳过）。
- **门槛**：jd 表新增 `score_threshold`、`threshold_suggestion`、`threshold_confirmed_by/at`；外发入口统一校验。
- **评分**：ScoringEngine 前置职能校验门禁（三态：匹配/不匹配/待确认）；门槛取岗位值。
- **提示词（2026-09-28 迁移）**：三处 AI 系统提示词（评分/话术/门槛建议）以 AgentScope 技能包维护于 `backend/src/main/resources/agents/skills/<name>/SKILL.md`（YAML frontmatter：name/description/version + 正文，正文为注入模型的 systemPrompt 唯一来源）；运行期经 `AgentSkillLoader` 加载（主路径 ClasspathSkillRepository，fat-jar 目录枚举异常时回退直读同一 MarkdownSkillParser 解析器；实测生产 fat-jar 走回退）；静态注入，三处仍为单轮 chat，行为与成本不变；修改 SKILL.md 需重启生效。
- **打招呼**：移除每日配额拦截；保留节奏、防重复、SEND_FAILED 重试；发送前复核四条件。
- **收集**：已知候选人附件收集已重构为纯接口路线（2026-09-27 上线）：卡片数据实际在消息 `payload.ext.extBody.bizData`（`bizType=7`，含 `attachmentResume.param → attachmentSign`）；CLI `attach-fetch` 检出后用 `get-resume-attachment` 换 `accessPath`，经浏览器下载通道落盘并校验，`saveResumeFile` 入库（文件名取自接口）；不打开会话（零已读副作用）。粒度防抖：`greeting_record.attach_probe_msg_id`——同一会话最新消息 ID 只探测一次；无附件记标记、失败不记标记（下轮重试）。旧“消息体扫描”仅保留给陌生来话兜底路径。
- **配额字段**：保留数据库列（仅展示参考），移除执行层拦截。

### 4.3 前端

- 岗位管理：门槛建议确认卡片（建议+理由+确认/修改）；行内「筛选与沟通」入口（该岗位候选人：评分、招呼、附件状态）。
- 候选人库：更名「已收简历」，仅入库成功者；新增「待分配」视图（无岗位/岗位已删，含附件）；
- 账号页：每日配额字段标注为「平台权益参考」。

## 5. 数据模型变更

| 变更 | 说明 |
|------|------|
| jd 表 +4 列 | 门槛/建议理由/确认人/确认时间 |
| score_record | 已有 (candidate, jd) 维度，支撑多岗位分别评分 |
| greeting_record | 已有 liepin_job_id（审计）；防重复为全局单人 |
| resume_file | 已有（bucket/key/format/size/sha256）；新增下载失败轨迹（状态或日志） |
| candidate.jd_id | 保留为「首次发现岗位」；岗位多关联由 score_record 表达 |

## 6. 安全与风控

- 单账号串行；每轮平台调用量 = 1 次会话轮询 + 岗位数 × 1 次推荐 + 新增打招呼（30 秒间隔）。
- 风控特征（安全验证/403/captcha/页面清空）→ 立即停止本轮 + 告警 + 熔断。
- 真机验证仅使用临时职位/已授权样本，不做破坏性操作。

## 7. 未决与未尽项

- 平台职能分类字段未核实：先以「期望标题映射 + 人工归一化」三态判定，分类证据不足时待确认。
- 推荐分页未验证：每岗位每轮首批 20 条；如岗位量大人选积压，再评估翻页（另行验证）。
- 附件为 PDF 已验证；其他格式（doc/docx）待样本验证。
- 运行窗口已拍板：每天执行（含周末与节假日，不做节假日/调休日历）。
- 单轮外发上限：已定义——每岗位 50（配置项，env 可调）；轮次由默认单线程调度器串行触发不重叠，长轮次顺延下一触发。
- 会话列表容量（2026-09-28 修正）：平台对 `pageSize>50` **静默降级为默认 20**（请求 100 实得 20，造成轮询看不到"被挤出窗口"候选人的会话盲区——890/873 因此漏派索要），且 `curPage` 已被平台忽略（分页失效）。CLI 已钳制为单页 50；轮询会话可见性恢复（50 条，含此前盲区候选人）。
- 来信轮询可靠性：子进程输出管道死锁已修复（大输出转临时文件）；非风控类拉取失败轮内重试一次（2026-09-26）。
- 多账号调度归属：现取第一个 NORMAL 账号；多账号轮询分配待确认。
- **附件检测与收集（已解决，2026-09-27）**：真机定位到卡片数据在消息 `ext.bizData`（bizType=7），非消息体；已由 CLI `attach-fetch` + 后端防抖/入库重构完成（徐先生附件 521023 字节真机入库验证）。遗留限制：仅校验 PDF（doc/docx 留待样本）；陌生人（未打过招呼）附件路径未扩（仍不探测）。
- **索要确认口径（已解决，2026-09-27~28）**：定位到 DOM 上的 `.action-resume` 按钮点击无任何 API/状态变化（死按钮）；真正生效的是 `com.liepin.im.b.askfor.send-askfor-request`（`oppositeImId`+`bizType=3`）。CLI 改为直调接口、由后端注入候选人快照 `im_id`（实测 resume-view 响应不含 im 字段），接口 `flag=1` 即确认；新增防重复：24h 窗口 + 累计最多 2 次（旧的"未确认保留原状态"曾导致 30 分钟内重复索要）。真机验证：8 例索要确认、890 索要后 12 分钟内候选人发来简历并自动入库（刘敬喜简历.pdf，263151 字节）。
- **打招呼 DOM 链路卡死（已解决，2026-09-27）**：定位到根因——puppeteer 的 `waitForSelector` 默认用 rAF 轮询、`page.click` 依赖页面内 IntersectionObserver，而 Chrome 会挂起**不可见页签**的渲染帧回调；用户打开其他页签后自动化页签转入后台，等待永不完成，挂满 60s 协议超时报 `Runtime.callFunctionOn timed out`（当日 82 次，候选人只收到预设招呼语）。CLI 新增 `waitForSelectorSafe`/`clickSafe`（Node 侧轮询 + `Runtime.evaluate`，与页签可见性无关）替换全部渲染帧依赖调用；真机验证：一轮内 30 人补发成功、0 失败（修复前 0 成功）。
- **风控关键词误熔断（已解决，2026-09-27）**：`RISK_KEYWORDS` 含泛英文词（`verify`/`captcha` 等）且连同成功命令的业务数据 stdout 一起扫描，候选人简历含 `verify`（硬件/验证方向常见）即误熔断并停轮。已分档：泛英文词仅在失败/超时路径扫描，精确标记（`safe.liepin.com`/`行为异常`/`captchaPage` 等）仍全路径扫描。2026-09-28 二次治理：中文短语（`安全验证`/`滑块验证`/`行为异常`）同样降级为仅失败路径扫描（候选人简历里的“涉水安全验证”曾致连续三轮误熔断），成功路径只保留结构性标记（`captchaPage`/`safe.liepin.com`）——误报类清零。
- **外发节奏阈值（2026-09-27/28 实测）**：连续约 30 次打招呼（约 40s 间隔）或**约 7 次索要/6 分钟**后平台真实触发「行为异常」/「安全验证」（页签跳转验证码页、业务接口静默拦截），账号按设计熔断停轮；触发后需人工在浏览器完成安全验证再恢复。
- **熔断治理落地（2026-09-28）**：外发定档 **60s/15/5**（间隔/单轮招呼/单轮索要），评分读取限速（单岗位 10、轮内跨岗位合计 30、间隔 2s——读取量是平台足迹大头）；新增**冷却窗口**：重置（账号更新或扫码登录）后默认 120 分钟暂停主动外发，轮次先做一次 chatlist 轻探测——通过则本轮只收不发，被跳验证页则立即停轮（不自伤）；手动 SQL 重置账户需同时写 `risk_reset_at=NOW()` 才进冷却。

## 8. 验收标准

1. 门槛未确认的岗位绝不外发（可测）。
2. 期望职能不匹配的人选绝不进入打招呼（可测）。
3. 附件仅在校验通过后入库；失败可重试且不重复入库（可测）。
4. 每天窗口内按小时自动运行，熔断即停（可测）。
5. 候选人库只显示入库成功者（可测）。
